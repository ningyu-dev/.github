## 方向

从钢结构厂房屋面雨水设计切入，一个系统一个行业，覆盖天沟、雨水斗、悬吊管、立管的完整计算链路。

选择这个切口的原因：系统边界清晰、变量由结构专业给定、计算密集且可查证、痛点真实，且单人可以完成闭环验证。

不做端到端的全自动设计，也不替代工程师签字。

## 三个技术判断

**规范知识库做结构化，不做 RAG。** 校验需要的是可比较的值而非文字，且 RAG 输出不可复现，而工程交付物要求确定性。详见 [lab/001](https://github.com/ningyu-dev/lab/blob/main/notes/001-为什么规范知识库不能做RAG.md)。

**规范原文不做本地推算。** 暴雨强度等参数依赖当地气象数据，算错了用户无法察觉，因此要求外部输入。

**自主决策必须可追责。** 每一步记录依据的规范条文号、所做的假设、被排除的方案及原因。假设允许存在，但必须显式标注。
